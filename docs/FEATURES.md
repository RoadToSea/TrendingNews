# TrendRadar Web 功能说明文档

本文档描述 TrendRadar Web 当前提供的核心功能、业务页面、采集与分析机制、配置能力以及权限边界。

---

## 1. 系统概览

TrendRadar Web 是一套面向自托管部署的多平台热点聚合、跨天趋势研判与报告归档系统：

- **后端**：基于 FastAPI + SQLite（WAL 模式）+ APScheduler（单 Worker 常驻调度），内置认证授权、配置加密存储、并发采集、AI 网关与多用户增量 Webhook 推送服务。
- **前端**：基于 React + TypeScript + Vite + Tailwind CSS + shadcn/ui + ECharts 构建，统一部署在 `/radar/` 子路径下，支持桌面端顶部导航与移动端底部导航自适应。

---

## 2. 多源数据采集与渐进式更新

系统由后台调度器或管理员手动触发，采用单次全量采集入库、全站共享阅读的机制：

| 数据源类型 | 采集方式与内置来源 | 关键特性 |
| --- | --- | --- |
| **国内热榜平台** | 基于 NewsNow 兼容接口（默认内置 14 个源：今日头条、百度热搜、华尔街见闻、澎湃新闻、bilibili 热搜、财联社热门、凤凰网、贴吧、微博、抖音、知乎，以及参考消息、联合早报、财联社电报） | 支持自定义 `api_url`、代理与新增平台；支持 `expected_domain` 校验返回链接是否为 HTTPS 且匹配预期域名；失败自动抖动重试 |
| **RSS / Atom / JSON Feed** | 支持 RSS 2.0、Atom 1.0 与 JSON Feed 1.1；内置国家统计局、中新网、界面新闻、Google News 定向检索及 BBC、FT、Nature、TechCrunch、Hacker News 等订阅源 | 支持按全局或单个订阅源设置 `max_age_days`（文章新鲜度过滤）与 `max_items` 条数上限；管理后台提供常用权威源一键预设 |
| **海外公开社区 API** | 支持 Hacker News（Firebase API）、Hugging Face（Daily Papers & Models）、GitHub（热门项目，可选 Token）、Reddit（指定 Subreddit）、YouTube（无密钥频道 Atom Feed） | 支持分源开关、最低热度/点赞/Star 阈值、拉取条数限制与统一代理配置 |

### 渐进式采集与实时状态反馈

- 管理员在业务页面点击顶部导航栏「**更新数据**」后，后端通过 `POST /api/jobs/crawl/stream` 建立 SSE 流式通道。
- 顶部进度条实时展示已完成来源数、最近完成的来源名称、新增条数及失败状态；页面列表随各来源落库静默刷新。
- 内置并发互斥锁，同一时刻仅允许执行一次全量采集（并发触发返回 HTTP `409`）；支持展开查看每个失败来源的具体错误原因。

## 3. 核心业务页面

### 3.1 平台热点（`/platforms`）

分为三个标签页展示最新采集内容：

- **平台热榜**：按平台筛选与关键词模糊搜索，展示当前榜单排名、领域标签、增速徽章与额外热度指标。
- **飙升榜**：按增速（`velocity`）降序排列最近 24 小时内的快速升温条目，突出显示新晋高热或排名大幅攀升的内容。
- **RSS 订阅**：按订阅源筛选最近 3 天的媒体文章，展示摘要、来源与发布时间。

支持勾选任意多条新闻卡片，一键触发 **AI 组合新闻深度分析** 或直接导入右下角 **AI 研判助手**。

### 3.2 领域聚合（`/domains`）

- 默认定位到今日日期，支持按日期与领域筛选查看 AI 自动归并的跨平台热点事件与同领域 RSS 文章；内置 7 个默认领域（`AI大模型`、`科技互联网`、`财经金融`、`宏观政策`、`国际地缘`、`社会民生`、`其他`）。
- 每张事件卡片展示综合热度指数、当日排名、覆盖平台数、事件摘要及关联报告链接；支持展开查看同源跨平台报道列表、点击「**问 AI**」直接携带事件上下文对话，或在选定具体领域后一键生成**领域趋势报告**。

### 3.3 趋势图谱（`/trends`）

- 基于 ECharts 展示近期热点走势，支持切换时间窗口（近 7 / 14 / 30 天）、每日展示上限（Top 5 / 10 / 15）及领域过滤。
- 横轴以**今日**为中心对称展开，纵轴为事件综合关注度；连续多天上榜的事件以彩色折线串联，单日事件以独立圆点展示，同日同分点位自动微错位以避免完全遮挡。
- 支持鼠标滚轮/手势缩放、画布拖拽平移，以及右上角「**复原视图**」一键重置视角。
- 点击图谱中的任意节点可打开右侧抽屉，查看事件摘要、多日热度变化轨迹、关联原始报道，并支持一键生成**每日总体报告**、**单事件深度分析报告**或加入 AI 对话上下文。

### 3.4 报告归档与词频分析（`/reports`）

分为两个标签页：

- **报告归档**：
  - 统一管理四类结构化 Markdown 报告：`daily_overall`（每日总体）、`domain_trend`（领域趋势）、`item_analysis`（新闻/事件深析）、`chat_generated`（对话生成）。
  - 支持按报告类型与日期筛选（切换报告类型时自动回到外侧报告清单）、可拖拽调整左右分栏比例（桌面端列表 + 正文阅读器）、移动端列表/详情切换、手动触发 AI 生成指定日期的总体或领域报告（默认日期为今日），以及删除归档报告。
- **关键词词组分析**：
  - 根据当前登录用户的个人「关注话题」规则，实时统计最近时间窗口内热榜与 RSS 的命中条数，按命中数量降序展示各词组及明细条目。

## 4. AI 研判助手（全局悬浮对话）

在业务页面右下角可呼出全局悬浮对话抽屉，其上方配有「**回到页面顶部**」快捷按钮：

- **点选上下文注入**：点击「选择页面新闻」进入点选模式后，可直接在页面上点选热点事件、热榜新闻、RSS 文章或历史归档报告作为结构化上下文芯片；退出选择模式后直接返回对话窗口。
- **精简流式对话**：对话窗口聚焦选择会话、创建新对话、流式提问与中止生成（使用系统当前启用的 AI 模型与默认开场提示词），历史会话的查看与删除统一在「个人配置中心 -> 会话管理」中进行。
- **一键沉淀为报告**：支持将当前会话的全部对话或指定问答轮次直接交由 AI 提炼并归档至报告库。

## 5. 核心算法与自动化机制

### 5.1 增速与综合热度模型

- **榜单类增速（`velocity`）**：结合相邻采样点（间隔 ≥ 20 分钟优先）的排名分值每小时爬升速率，以及首次出现 2 小时内冲入 Top 15 的新晋加分。
- **互动类增速（`velocity`）**：针对 Hacker News、Hugging Face、GitHub、Reddit、YouTube 等带原生互动指标的来源，先计算每小时互动增长率，再按平台内进行 `log1p` 分位数与最大值比例加权归一化至 `[0, 100]`。
- **事件综合热度指数（`hot_index`，`[0, 100]`）**：默认按跨平台覆盖率（`0.35`）、各平台最佳排名均分（`0.35`）、当日多批次在榜持续性（`0.20`）与最高单条增速（`0.10`）加权计算。

### 5.2 跨语言 AI 事件归类

- 每次手动或定时采集后，调度绑定的 `event_cluster` 模型槽位，扫描最近 48 小时内尚未关联事件的新闻，对照近 3 天已有事件簇与系统领域定义进行中英文跨平台归并，并实时重算当日事件热度与排行指标。

### 5.3 关键词匹配与多用户增量推送

- 服务器端**单次定时采集**后，遍历所有已启用且开启个人推送的成员配置：
  - 按各自「关注话题与屏蔽词」过滤近 24 小时新采集内容；
  - 结合 `user_webhook_deliveries` 去重表过滤已发送条目，仅推送上次之后新命中的**增量内容**，避免重复打扰；
  - 各用户通道独立异常隔离，发送超时控制为 10 秒。

词组规则按空行分块，支持以下语法：

| 语法 | 作用域 | 说明 |
| --- | --- | --- |
| `[GLOBAL_FILTER]` | 全局 | 区域标记，其后词条命中则全局排除（支持正则） |
| `[WORD_GROUPS]` | 词组区 | 区域标记，开启关注词组定义（默认区域） |
| `[组别名]` | 当前词组 | 写在词组第一行，指定该组统计显示名称 |
| `/正则/` | 词条 | 正则表达式匹配（默认忽略大小写） |
| `词 => 别名` | 词条 | 为单条关键词指定显示别名 |
| `+词` | 当前词组 | 必须词，组内所有 `+` 词均需同时匹配 |
| `!词` | 当前词组 | 组内排除词，命中则仅排除当前词组（不影响其他词组） |
| `@数字` | 当前词组 | 限制该词组最多返回的条目数 |

### 5.4 后台定时调度（APScheduler）

- **定时采集任务**：默认每 30 分钟执行一次（可配置，最低 5 分钟），依次执行多源采集、增量事件聚类与多用户增量 Webhook 分发。
- **每日总体报告任务**：按配置时间（默认 `22:00`）自动检测 `summary_report` 模型槽位并生成当日总体热点报告。
- **热重载生效**：管理员在管理后台修改定时参数后，运行中的调度器立即动态重排任务，无需重启服务。

## 6. 个人配置中心（`/settings`）与管理后台（`/admin`）

### 6.1 个人配置中心（所有成员可用）

1. **关注话题**：配置个人全局屏蔽词、关注词组及是否纳入 RSS 统计，后台自动静默保存。
2. **消息推送**：独立配置个人 Webhook 开关与推送地址，支持 **飞书**、**钉钉**、**企业微信**、**通用 Webhook** 共 4 种通道；输入框失焦后自动加密保存并提供「测试推送」。
3. **会话管理**：浏览个人全部历史 AI 对话会话，支持一键跳转打开或删除。
4. **开场提示词**：管理 AI 研判助手的系统开场提示词模板与默认选中项。
5. **账户设置**：查看当前登录账号与角色，支持修改登录密码。

### 6.2 管理后台（仅 `admin` 角色可访问）

1. **数据源与领域**：管理国内热榜平台、海外公开 API 源、RSS 订阅源、领域分类字典与统一网络代理。
2. **AI 模型配置**：管理 **Google AI Studio (Gemini)**、**OpenAI 兼容接口** 与 **Anthropic 接口** 凭据；支持连通性探测、在线拉取模型列表与一键激活主力槽位。
3. **定时与趋势**：配置全站自动采集间隔、每日总体报告触发时间、本地数据保留天数与趋势图默认每日 Top N。
4. **邀请码管理**：签发自定义或随机邀请码，设置次数/过期时间/备注、启停或复制含邀请码的注册链接（`/radar/register?code=...`）。
5. **成员账号管理**：查看成员来源邀请码与最近登录时间，调整角色或停用账号（停用后对方登录会话立即失效）。

## 7. 安全机制与数据隔离边界

- 密码采用 **Argon2** 哈希存储；登录与注册均内置基于客户端 IP 的滑动窗口限流；会话通过受 `/radar/` 子路径约束的 `HttpOnly` 签名 Cookie 维持。
- 第三方 AI API Key、Webhook 地址与数据源密钥均使用 **Fernet** 对称加密落库，API 仅返回掩码。

| 数据范围 | 涉及内容 | 访问与隔离规则 |
| --- | --- | --- |
| **全站共享业务内容** | 采集到的热榜/RSS 数据、聚类事件、归档报告、领域分类字典、开场提示词模板 | 所有已登录成员可浏览；全局数据源/AI 模型/定时配置与手动采集仅管理员可操作 |
| **用户私有配置与数据** | 关注话题与屏蔽词、消息推送 Webhook 配置、推送去重记录、AI 对话会话历史 | 严格按 `user_id` 隔离，互不影响 |
| **管理员专属治理** | `/admin` 及 `/api/admin/*`、`/api/ai-providers*`、`/api/jobs/crawl/*`、系统级设置写入 | 仅 `admin` 角色可访问，普通成员请求返回 `403` |
